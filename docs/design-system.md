# 개인 여행 아카이브 디자인 시스템

작성일: 2026-05-08  
기준 문서: `docs/travel_archive_prd.md`, `docs/ui_brief.md`  
기준 시안: `docs/design` 폴더의 최종 시안. 단, `concept_web.png`, `concept_mobile.png`는 초기 컨셉 시안으로 보고 최종 기준에서 제외한다.

## 1. 최종 디자인 컨셉

최종 디자인 컨셉은 **따뜻한 여행 기록장 기반의 모바일 우선 PWA**다.

서비스는 지도와 통계 중심의 기능형 앱이지만, 시각 톤은 차갑고 복잡한 대시보드보다 개인 여행 다이어리에 가깝게 유지한다. 사진 중심 카드, 부드러운 크림 배경, 코랄/틸 포인트, 둥근 이미지 카드, 손으로 기록하는 듯한 여백감을 사용한다.

다만 PRD의 핵심 기능인 지도 전략은 반드시 유지한다.

- 해외/국내 대시보드 지도는 `react-simple-maps` 기반 색칠 지도다.
- 해외여행은 국가 단위로 표시한다.
- 국내여행은 MVP에서 시/도 단위로 표시한다.
- 여행 상세 장소 지도는 `Leaflet` 기반 장소 핀 지도다.
- 상세지도에서는 지역 색칠을 하지 않는다.

최종 시안 충족도:

- 홈 대시보드, 여행 목록, 버킷리스트 전환, 통계, 마이페이지는 PRD/UI 브리프 요구사항을 잘 충족한다.
- 지도 바텀시트는 모바일 PWA 패턴에 적합하게 표현되어 있다.
- 웹 화면은 모바일 디자인 시스템을 넓은 화면으로 확장한 형태로 자연스럽다.
- 보완이 필요한 부분은 여행 상세 화면의 타임라인, Leaflet 장소 지도, 사진/메모 기록 전용 화면이다. 최종 시안에 약하게 표현되어 있으므로 구현 시 이 문서의 여행 상세 규칙을 기준으로 보완한다.

최종 방향:

- 기존 최종 시안의 감성적인 여행 기록장 스타일을 유지한다.
- 새로운 디자인 컨셉을 추가하지 않는다.
- 모바일 PWA를 1차 기준으로 삼고, 웹은 같은 디자인 시스템을 확장한 반응형 화면으로 구현한다.
- MVP 구현 범위를 벗어나는 추천, 공유, AI, 동선 라인, 시/군/구 지도는 UI에서 과하게 암시하지 않는다.

## 2. 컬러 팔레트

최종 시안은 따뜻한 오프화이트 배경과 코랄/틸 포인트를 사용한다. 색상은 감성적인 톤을 유지하되 상태 의미가 흐려지지 않게 토큰화한다.

### 2.1 기본 색상

- `Background`: 따뜻한 크림/오프화이트. 앱 전체 배경.
- `Surface`: 거의 흰색에 가까운 카드 배경.
- `SurfaceMuted`: 연한 베이지. 보조 카드, 입력 영역, 하단 안내 영역.
- `TextPrimary`: 진한 브라운 블랙 또는 다크 그레이. 제목과 주요 텍스트.
- `TextSecondary`: 중간 톤 그레이 브라운. 설명, 날짜, 부가 정보.
- `TextMuted`: 낮은 대비 그레이. 보조 라벨, 비활성 정보.
- `Border`: 옅은 베이지 그레이. 카드 경계와 구분선.

### 2.2 포인트 색상

- `PrimaryCoral`: 주요 CTA, 활성 탭, 중요한 상태 강조.
- `PrimaryTeal`: 지도 토글 선택, 완료 상태, 보조 CTA.
- `SoftBlue`: 지도/통계의 차분한 보조 강조.
- `WarmAmber`: 예정, 리마인더, D-day 같은 시간성 강조.
- `Lavender`: 버킷리스트, 저장 항목, 보조 상태.

### 2.3 상태 색상

지도와 배지는 같은 의미 체계를 사용한다.

- `COMPLETED`: 틸/그린 계열. 방문 완료.
- `PLANNED`: 코랄/앰버 계열. 예정 여행.
- `BUCKET`: 라벤더/소프트 퍼플 계열. 버킷리스트.
- `CANCELLED`: 회색 계열. 취소.
- `ON_HOLD`: 회색 또는 낮은 채도의 앰버. 보류.

주의사항:

- 색상만으로 상태를 전달하지 않는다. 상태 텍스트를 항상 함께 제공한다.
- 지도, 배지, 차트의 색상 의미가 서로 달라지지 않게 한다.
- 전체 화면이 베이지/코랄 한 계열로만 보이지 않도록 지도와 차트에는 틸/블루 계열을 함께 사용한다.

## 3. 타이포그래피

앱 내부 타이포그래피는 가독성이 우선이다. 감성적인 손글씨 느낌은 이미지 시안이나 마케팅성 장식에만 제한하고, 실제 앱 UI는 산세리프 기반으로 구현한다.

권장 크기:

- 페이지 제목: 24-28px
- 화면 섹션 제목: 18-20px
- 카드 제목: 16-18px
- 본문: 14-16px
- 보조 설명: 12-13px
- 배지/칩: 11-13px
- 통계 숫자: 24-32px

규칙:

- 모바일에서 제목은 2줄까지 허용한다.
- 긴 여행명과 지역명은 카드에서는 1-2줄 말줄임 처리한다.
- 숫자 지표는 라벨보다 시각적으로 강하게 표현한다.
- 웹에서도 모바일과 같은 계층을 유지하되, 최대 폭과 카드 배치로 여백을 조절한다.

## 4. 레이아웃 원칙

### 4.1 모바일

- 모바일은 1컬럼 구조를 기본으로 한다.
- 하단 탭 네비게이션을 고정한다.
- 주요 액션은 하단 탭 위 또는 우측 하단에 둔다.
- 지도 선택, 필터, 확인 액션은 바텀시트를 우선 사용한다.
- 콘텐츠 하단에는 하단 탭과 safe-area를 고려해 충분한 여백을 둔다.

### 4.2 웹

- 웹은 모바일 디자인을 확장한 반응형 레이아웃이다.
- 좌측 사이드바를 사용할 수 있다.
- 홈과 통계는 넓은 화면에서 카드 그리드와 사이드 패널을 활용한다.
- 웹 전용 기능을 추가하지 않고 정보 배치만 넓은 화면에 맞게 재구성한다.

### 4.3 공통

- 카드 내부에 카드를 중첩하지 않는다.
- 정보 우선순위는 사진/지도, 핵심 숫자, 다음 행동, 상세 목록 순으로 배치한다.
- 스크롤 화면에서 상단 영역은 짧게 유지하고 본문 정보 접근성을 높인다.
- 상태 필터는 세그먼트 컨트롤 또는 칩으로 표현한다.

## 5. 카드 스타일

카드는 최종 시안의 핵심 구성 단위다.

기본 규칙:

- 배경은 밝은 `Surface`를 사용한다.
- radius는 12-18px 범위를 허용하되, 입력 필드와 작은 칩은 더 작게 사용한다.
- 그림자는 부드럽고 낮은 강도로 사용한다.
- 테두리는 `Border` 색상으로 매우 약하게 사용한다.
- 카드 간 간격은 모바일 기준 12-16px를 유지한다.

카드 유형:

- `HeroImageCard`: 여행 대표 이미지와 제목/기간/상태를 겹쳐 보여준다.
- `StatCard`: 핵심 숫자와 아이콘을 보여준다.
- `TripCard`: 여행명, 기간, 지역, 상태, 이미지, 액션을 보여준다.
- `ChecklistCard`: 진행률과 체크 항목을 보여준다.
- `BucketCard`: 버킷리스트 장소와 전환 CTA를 보여준다.
- `ChartCard`: 통계 차트를 담는다.
- `ProfileCard`: 마이페이지 사용자 요약을 보여준다.

주의사항:

- 홈의 지도 카드와 여행 이미지 카드는 시각적으로 가장 커야 한다.
- 작은 카드가 많아질 때는 동일한 그림자와 radius로 정돈감을 유지한다.
- 웹에서는 카드 크기가 너무 넓어지지 않도록 내부 최대 폭을 둔다.

## 6. 버튼 스타일

버튼은 감성적인 톤을 유지하되, 액션의 우선순위가 명확해야 한다.

### 6.1 Primary Button

용도:

- 예정 여행으로 전환
- 저장
- 완료 처리
- 주요 생성 액션

스타일:

- 코랄 계열 배경
- 흰색 텍스트
- 12-16px radius
- 모바일 기준 높이 48-56px

### 6.2 Secondary Button

용도:

- 상세 보기
- 체크리스트 보기
- 지도 보기
- 필터 초기화

스타일:

- 연한 베이지/오프화이트 배경
- 진한 텍스트
- 약한 테두리

### 6.3 Icon Button

용도:

- 알림
- 더보기
- 닫기
- 수정
- 좋아요/저장

스타일:

- 최소 터치 영역 44px
- 실제 아이콘 크기 18-22px
- 중요한 액션은 배경 원형 또는 작은 버튼 표면을 사용한다.

### 6.4 Floating Action Button

용도:

- 여행 추가
- 버킷리스트 추가
- 타임라인 항목 추가

규칙:

- 하단 탭과 겹치지 않게 배치한다.
- 화면당 하나만 사용한다.
- 웹에서는 우측 상단 CTA 버튼으로 대체할 수 있다.

## 7. 배지 스타일

배지는 상태, 범위, 우선순위, 카테고리를 짧게 표현한다.

여행 상태:

- `PLANNED`: 예정
- `COMPLETED`: 완료
- `CANCELLED`: 취소

버킷리스트 상태:

- `WANT_TO_GO`: 가고 싶어요
- `PLANNING`: 계획 중
- `BOOKED`: 예약 완료
- `VISITED`: 다녀옴
- `ON_HOLD`: 보류

여행 범위:

- 국내
- 해외

우선순위:

- 높음
- 보통
- 낮음

스타일 규칙:

- 텍스트 라벨을 반드시 포함한다.
- radius는 pill 형태를 기본으로 한다.
- 배지 색상은 상태 색상 토큰을 따른다.
- 이미지 위 배지는 충분한 대비를 위해 반투명 어두운 배경 또는 밝은 캡슐을 사용한다.

## 8. 하단 탭 네비게이션

모바일 PWA의 기본 네비게이션은 하단 탭이다.

탭 구성:

1. 홈
2. 여행
3. 버킷
4. 통계
5. 마이

탭별 책임:

- 홈: 지도 대시보드, 요약 지표, 다가오는 여행, 체크리스트 리마인더, 최근 여행.
- 여행: 예정/완료/취소 여행 목록, 여행 상세 진입, 여행 생성.
- 버킷: 가고 싶은 장소 목록, 버킷리스트 등록, 예정 여행 전환.
- 통계: 여행 횟수, 여행 일수, 방문 국가/지역, 월별 빈도, 순위 차트.
- 마이: 계정 정보, 앱 설정, 알림 설정, 지도 표시 설정, 데이터 관리, 도움말, 로그아웃.

스타일 규칙:

- 활성 탭은 코랄 계열로 강조한다.
- 비활성 탭은 그레이 아이콘과 라벨을 사용한다.
- 하단 safe-area를 고려한다.
- 탭 라벨은 짧게 유지한다.
- 탭은 주요 화면 전환 전용이며, 세부 액션은 화면 내부 버튼으로 처리한다.

웹 대응:

- 웹에서는 좌측 사이드바로 전환한다.
- 사이드바 메뉴 순서는 모바일 탭 순서와 동일하게 유지한다.

## 9. 지도 UI 규칙

지도는 PRD에서 정의한 역할 분리를 최우선으로 따른다.

### 9.1 대시보드 지도

용도:

- 홈 대시보드에서 세계/국내 여행 현황을 보여준다.

구현:

- `react-simple-maps` 사용.
- 세계지도는 국가 단위 색칠.
- 국내지도는 MVP에서 시/도 단위 색칠.
- 지도 위 오버레이는 최소화한다.

상태 우선순위:

```txt
COMPLETED > PLANNED > BUCKET
```

지도 색상:

- 완료: 틸/그린 계열
- 예정: 코랄/앰버 계열
- 버킷리스트: 라벤더 계열
- 데이터 없음: 낮은 대비 중립색

### 9.2 지도 토글

- 모바일에서는 `세계 / 국내` 세그먼트 토글로 하나의 지도만 표시한다.
- 웹에서는 기본적으로 동일한 토글 구조를 유지한다.
- 웹 홈에서 여백이 충분하면 세계지도와 국내지도를 병렬 카드로 보여줄 수 있다.

### 9.3 지도 선택 바텀시트/드로어

모바일:

- 지역 선택 시 바텀시트를 연다.
- 기본 높이는 화면의 35-45% 수준으로 시작한다.
- 확장 시 80-90%까지 올라갈 수 있다.

웹:

- 우측 드로어 또는 사이드 패널을 사용한다.
- 지도와 패널을 동시에 볼 수 있어야 한다.

표시 정보:

- 선택한 국가/지역명
- 한 줄 설명
- 완료 여행 수
- 예정 여행 수
- 버킷리스트 수
- 완료 여행 카드
- 예정 여행 카드
- 버킷리스트 미리보기

### 9.4 여행 상세 지도

용도:

- 여행 상세 화면에서 실제 방문 장소 핀을 보여준다.

구현:

- `Leaflet` 사용.
- 타임라인 항목의 위도/경도를 마커로 표시한다.
- 상세지도는 색칠 지도가 아니다.
- MVP에서는 동선 라인, 지도에서 장소 직접 추가, 장소 검색 API를 제외한다.

보완 필요:

- 최종 시안 세트에는 여행 상세 Leaflet 지도 전용 화면이 약하다. 구현 시 여행 상세의 `지도` 탭에서 반드시 별도 화면으로 제공한다.

## 10. 체크리스트 UI 규칙

체크리스트는 여행 준비 단계의 핵심 작업 화면이다.

구조:

- 상단 진행률 카드
- 카테고리 칩 또는 카테고리 섹션
- 체크 항목 리스트
- 항목 추가 버튼

표시 정보:

- 전체 진행률
- 완료 항목 수
- 전체 항목 수
- 카테고리명
- 항목명
- 완료 여부
- 마감일 또는 보조 설명

스타일 규칙:

- 완료 체크는 왼쪽에 배치한다.
- 완료된 항목은 체크 아이콘과 약한 텍스트 톤으로 구분한다.
- 진행률 바는 코랄 또는 틸 계열을 사용한다.
- 카테고리 아이콘은 감성적이되, 구현 부담을 줄이기 위해 공통 아이콘 세트를 사용한다.

상호작용:

- 체크 변경 시 진행률을 즉시 갱신한다.
- 항목 추가/수정은 바텀시트 또는 모달로 처리한다.
- 홈에서는 체크리스트 요약만 보여주고, 상세 체크는 체크리스트 화면에서 처리한다.

## 11. 타임라인 UI 규칙

타임라인은 완료 여행 기록의 중심 화면이다.

구조:

- 날짜 선택 칩
- Day별 타임라인 리스트
- 타임라인 항목 카드
- 사진 썸네일
- 장소 정보
- 항목 추가 FAB 또는 하단 버튼

표시 정보:

- Day 번호
- 날짜
- 시간
- 제목
- 장소명
- 메모 일부
- 사진 썸네일
- 카테고리 또는 비용

스타일 규칙:

- 세로 타임라인 축을 사용한다.
- 시간과 Day 라벨은 작지만 명확하게 표현한다.
- 사진이 있는 항목은 오른쪽 또는 하단 썸네일로 표시한다.
- 여행 상세에서는 `개요`, `타임라인`, `체크리스트`, `지도`, `사진` 내부 탭을 유지한다.

보완 필요:

- 최종 시안 세트에는 여행 상세 타임라인 전용 화면이 충분히 드러나지 않는다. 실제 구현에서는 PRD의 날짜별 타임라인과 사진/메모/장소 기록 요구사항을 반드시 반영한다.

## 12. 버킷리스트 카드 규칙

버킷리스트는 사진 중심 카드와 예정 여행 전환 흐름을 함께 제공한다.

카드 표시 정보:

- 장소 이미지
- 여행지명
- 국내/해외 구분
- 국가 또는 국내 지역
- 도시명
- 상태 배지
- 우선순위
- 희망 시기
- 예상 예산
- 태그
- 좋아요/저장 아이콘

주요 액션:

- 상세 보기
- 수정
- 삭제
- 예정 여행으로 전환

전환 화면 규칙:

- 버킷리스트 이미지를 큰 hero 카드로 보여준다.
- 기존 장소 정보는 폼에 미리 채운다.
- 여행명, 시작일, 종료일, 동행자, 여행 스타일을 입력한다.
- 자동 생성 체크리스트 미리보기를 보여준다.
- 하단 고정 primary 버튼으로 `예정 여행으로 전환`을 제공한다.

주의사항:

- 버킷리스트 화면과 통계 화면의 책임을 섞지 않는다.
- 버킷 탭에서는 통계 요약을 보조 정보로만 제한한다.

## 13. 통계 카드/차트 규칙

통계 화면은 감성 톤을 유지하되 데이터 가독성을 우선한다.

MVP 차트 우선순위:

1. 연도별 여행 횟수와 여행 일수
2. 월별 여행 빈도
3. 국가별 방문 횟수
4. 국내 지역별 방문 횟수

카드 구성:

- 상단 핵심 지표 2x2 카드
- 여행 형태별 비율 도넛 차트
- 월별 여행 횟수 막대 차트
- 최다 방문 국가 순위
- 최다 방문 지역 순위

스타일 규칙:

- 차트 색상은 지도/배지 상태 색상과 충돌하지 않게 한다.
- 범례는 간단한 텍스트와 색 점으로 제공한다.
- 모바일에서는 차트 카드를 세로로 배치한다.
- 웹에서는 2컬럼 그리드를 사용한다.
- 차트 카드 안에 설명을 과도하게 넣지 않는다.

후순위:

- 총 여행 비용
- 도시별 방문 횟수
- 대륙별 통계
- 여행 유형 상세 분석

## 18. 프론트엔드 구현 시 주의사항

### 18.1 MVP 범위 관리

- 최종 시안의 시각 완성도를 그대로 모든 화면에 적용하려고 하지 않는다.
- 홈, 여행, 버킷, 통계, 마이의 기본 구조를 먼저 구현한다.
- 여행 상세의 타임라인/지도/사진은 PRD 필수 기능이므로 최종 시안에 약하더라도 반드시 구현한다.
- 공유, AI, 시/군/구 지도, 동선 라인, 장소 검색은 MVP에서 제외한다.

### 18.2 지도 구현

- `react-simple-maps`와 `Leaflet`의 책임을 분리한다.
- 홈 지도는 지역 상태 집계만 담당한다.
- 상세 지도는 장소 핀만 담당한다.
- 지도 컴포넌트는 SSR 이슈를 고려해 Next.js에서 클라이언트 컴포넌트로 분리한다.
- 지도 영역은 고정 높이와 로딩 상태를 가져야 한다.

### 18.3 이미지 처리

- 모든 이미지 카드에는 fallback 이미지를 둔다.
- 이미지 로딩 중 skeleton을 제공한다.
- 모바일에서는 이미지 비율을 고정해 레이아웃 점프를 줄인다.
- MVP에서는 썸네일 자동 생성 없이 업로드된 이미지를 제한적으로 사용한다.

### 18.4 접근성과 사용성

- 모든 아이콘 버튼에는 접근 가능한 라벨을 제공한다.
- 색상만으로 상태를 구분하지 않는다.
- 주요 터치 영역은 최소 44px 이상으로 유지한다.
- 하단 탭과 FAB는 safe-area를 고려한다.
- 긴 텍스트는 줄바꿈 또는 말줄임 기준을 둔다.

### 18.5 컴포넌트 설계

- 모바일과 웹에서 같은 컴포넌트를 재사용하되 레이아웃 래퍼만 변경한다.
- 카드, 배지, 버튼, 칩, 차트, 지도 패널은 디자인 토큰을 공유한다.
- 상태 색상은 하드코딩하지 않고 토큰으로 관리한다.
- 화면별 API 연동 전에도 샘플 데이터로 동일한 UI를 검증할 수 있게 한다.

### 18.6 최종 시안 보완 항목

프론트엔드 설계 또는 추가 와이어프레임에서 다음 화면을 보완한다.

- 여행 상세 타임라인 화면
- 여행 상세 Leaflet 지도 화면
- 여행 상세 사진/메모 화면
- 지도 범례의 세부 표현
- 취소 여행 상태의 목록/상세 표현
