## 1. 서비스 UI 한 줄 설명

개인 여행 아카이브는 지도 기반 여행 회고 앱과 모바일 생산성 앱의 구조를 결합한 PWA로, 사용자가 가고 싶은 곳, 준비 중인 여행, 다녀온 여행을 손쉽게 기록하고 한눈에 돌아볼 수 있어야 한다.

---

## 2. 모바일 우선 UX 방향

### 2.1 모바일 사용자가 가장 자주 할 행동

사용자는 모바일에서 짧고 반복적인 행동을 자주 수행한다.

- 여행지 또는 버킷리스트 빠른 등록
- 예정 여행의 체크리스트 확인 및 완료 체크
- 여행 중 또는 여행 후 타임라인 항목 추가
- 사진, 메모, 장소 정보 추가
- 홈에서 지도와 통계 요약 확인
- 예정 여행과 최근 여행 기록으로 빠르게 재진입

### 2.2 한 손 조작을 고려한 UI 방향

- 주요 내비게이션은 하단 탭에 배치한다.
- 생성 액션은 화면 우측 하단의 플로팅 액션 버튼 또는 각 탭의 고정 하단 버튼으로 제공한다.
- 체크리스트 완료, 타임라인 추가, 사진 추가 같은 빈번한 액션은 엄지손가락이 닿기 쉬운 하단 영역에 둔다.
- 지도 화면에서는 상단보다 하단 바텀시트로 상세 정보를 보여준다.
- 카드와 리스트 항목은 터치하기 쉬운 높이로 구성하고, 주요 액션은 최소 44px 이상의 터치 영역을 확보한다.

### 2.3 PWA 앱처럼 보이기 위한 기준

- 브라우저 웹페이지보다 네이티브 앱에 가까운 고정 하단 탭 구조를 사용한다.
- 상단 주소창이 줄어드는 모바일 브라우저 환경에서도 핵심 액션이 가려지지 않도록 safe-area를 고려한다.
- 화면 전환은 탭, 상세 진입, 바텀시트, 모달 중심으로 단순하게 유지한다.
- 오프라인 기능은 MVP 필수는 아니지만, PWA 설치 후 홈 화면에서 실행되는 앱처럼 헤더와 네비게이션을 안정적으로 유지한다.
- 로그인 이후에는 랜딩 페이지가 아니라 홈 대시보드가 첫 화면이어야 한다.

### 2.4 웹/데스크탑 대응 수준

MVP의 기준은 모바일이다. 데스크탑은 모바일 화면을 넓히는 보조 대응으로 설계한다.

- 모바일: 핵심 사용 환경. 하단 탭, 단일 컬럼, 바텀시트 중심.
- 태블릿: 2컬럼 일부 허용. 지도와 목록을 나란히 보여줄 수 있다.
- 데스크탑: 포트폴리오 시연과 관리 편의성 고려. 중앙 최대 너비 레이아웃 또는 지도+사이드 패널 구조를 사용한다.
- 데스크탑 전용 고급 기능은 MVP 범위에 포함하지 않는다.

이 서비스는 웹 기반 Next.js 애플리케이션이지만, 제품 경험의 1차 기준은 모바일 PWA다. 따라서 별도의 웹 전용 UI 브리프를 만들기보다 이 문서를 단일 UI 기준 문서로 사용한다. 웹 화면은 별도 제품이 아니라 같은 디자인 시스템을 넓은 화면으로 확장한 반응형 표현으로 본다.

별도 웹 UI 브리프가 필요한 경우는 데스크탑 웹이 1차 사용 환경이 되거나, 지도+목록 동시 편집, 키보드 중심 대량 입력, 관리자형 테이블, 대량 데이터 관리처럼 데스크탑 전용 워크플로우가 핵심이 될 때다. 현재 MVP 범위에서는 해당하지 않는다.

모바일/웹 시안의 역할 차이:

- 모바일 시안은 실제 PWA 구현 기준이다. 하단 탭, 단일 컬럼, safe-area, 바텀시트, 한 손 조작을 우선한다.
- 웹 시안은 포트폴리오 시연과 큰 화면 설명력을 위한 보조 기준이다. 좌측 사이드바, 넓은 지도 카드, 병렬 정보 배치를 사용할 수 있다.
- 기능 범위는 모바일 MVP 기준을 우선하며, 웹에서 보이는 고밀도 정보 배치는 구현 여력이 있을 때 확장한다.
- 모바일과 웹이 서로 다른 제품처럼 보이지 않도록 색상, 카드, 배지, 지도, 차트, 상태 표현은 같은 디자인 토큰과 컴포넌트 규칙을 공유한다.

## 3. 핵심 사용자 흐름

### 3.1 버킷리스트 등록

화면 흐름:

```txt
버킷리스트 탭
-> 버킷리스트 목록
-> 추가 버튼
-> 버킷리스트 등록 폼
-> 저장
-> 버킷리스트 상세 또는 목록 복귀
```

화면별 UI 포인트:

- 목록에서는 국내/해외, 국가/지역, 우선순위, 희망 시기, 상태를 카드로 보여준다.
- 등록 폼은 필수값을 먼저 받고, 이유/예산/태그/참고 링크는 접을 수 있는 추가 정보 영역에 둔다.
- 저장 후에는 "예정 여행으로 전환" 액션을 바로 노출한다.

### 3.2 버킷리스트를 예정 여행으로 전환

화면 흐름:

```txt
버킷리스트 상세 또는 카드 액션
-> 예정 여행으로 전환
-> 여행 기간/여행명 확인
-> 기본 체크리스트 생성 안내
-> 전환 완료
-> 여행 상세 화면
```

화면별 UI 포인트:

- 전환 화면은 새 여행 생성 폼처럼 보이되, 버킷리스트에서 가져온 지역 정보는 미리 채운다.
- 여행명, 시작일, 종료일, 국가 또는 시/도, 도시명을 명확히 입력하게 한다.
- 전환 완료 후 다음 행동은 체크리스트 확인이다.

### 3.3 여행 준비 체크리스트 확인

화면 흐름:

```txt
여행 탭
-> 예정 여행 카드
-> 여행 상세
-> 체크리스트 탭
-> 항목 완료 체크 또는 항목 추가
```

화면별 UI 포인트:

- 체크리스트 진행률을 상단에 크게 보여준다.
- 카테고리별로 묶어 스크롤 부담을 줄인다.
- 완료 체크는 리스트 왼쪽에 배치하고, 항목 수정은 우측 메뉴 또는 스와이프 액션으로 처리한다.

### 3.4 여행 완료 처리

화면 흐름:

```txt
여행 상세
-> 상태 배지 또는 더보기 메뉴
-> 완료 처리
-> 완료 조건 확인
-> COMPLETED 상태 변경
-> 기록 추가 안내
```

화면별 UI 포인트:

- 완료 처리는 실수 방지를 위해 확인 모달 또는 바텀시트로 처리한다.
- 완료 조건인 여행 기간과 최소 1개 이상의 여행 날짜가 부족하면 부족한 항목을 안내한다.
- 완료 후에는 타임라인, 사진, 장소 핀 기록으로 이어지는 CTA를 제공한다.

### 3.5 여행 타임라인 작성

화면 흐름:

```txt
여행 상세
-> 타임라인 탭
-> 날짜 선택
-> 타임라인 항목 추가
-> 시간/제목/메모/장소/사진 입력
-> 저장
```

화면별 UI 포인트:

- 날짜는 상단 가로 스크롤 칩으로 선택한다.
- 타임라인 항목은 시간, 장소명, 제목, 사진 썸네일을 우선 표시한다.
- 장소명, 주소, 위도, 경도 입력은 MVP에서 수동 입력을 기본으로 한다.

### 3.6 장소 핀 확인

화면 흐름:

```txt
여행 상세
-> 지도 탭
-> Leaflet 지도
-> 장소 핀 탭
-> 마커 요약 바텀시트
-> 연결된 타임라인 항목으로 이동
```

화면별 UI 포인트:

- 상세지도는 색칠 없이 장소 핀만 표시한다.
- 마커를 누르면 시간, 장소명, 메모, 사진 썸네일을 바텀시트로 보여준다.
- 지도에서 장소 직접 추가와 동선 라인은 MVP 제외임을 디자인에서도 암시하지 않는다.

### 3.7 세계지도/국내지도 대시보드 확인

화면 흐름:

```txt
홈 탭
-> 지도 대시보드
-> 세계지도/국내지도 토글
-> 국가 또는 지역 선택
-> 관련 여행/버킷리스트 바텀시트 확인
```

화면별 UI 포인트:

- 홈 첫 화면의 중심은 지도와 요약 지표다.
- 지도 전환 토글은 지도 상단에 명확히 배치한다.
- 지도 클릭 결과는 화면을 이동시키기보다 바텀시트로 먼저 보여준다.

### 3.8 통계 확인

화면 흐름:

```txt
통계 탭
-> 요약 지표
-> 연도별 여행 횟수/일수
-> 국가별/국내 지역별 방문 횟수
-> 월별 여행 빈도
```

화면별 UI 포인트:

- 모바일에서는 차트를 한 번에 하나씩 세로로 배치한다.
- 핵심 숫자 카드가 먼저 오고, 차트는 그 아래에 배치한다.
- 비용, 도시별 방문 횟수, 여행 유형 비율은 후순위 확장 요소로 분리한다.

## 4. 모바일 네비게이션 구조 제안

하단 탭 네비게이션을 기본 구조로 사용한다.

### 4.1 홈

역할:

- 지도와 여행 요약을 보여주는 첫 화면
- 세계지도/국내지도 전환
- 예정 여행, 체크리스트, 최근 여행 기록으로 빠른 진입

진입 화면:

- 홈 대시보드
- 지도 클릭 바텀시트
- 예정 여행 상세
- 최근 여행 상세

### 4.2 여행

역할:

- 예정 여행, 완료 여행, 취소 여행을 관리한다.
- 여행 상세, 타임라인, 체크리스트, 사진, 장소 지도로 진입한다.

진입 화면:

- 여행 목록
- 여행 등록/수정
- 여행 상세
- 체크리스트
- 타임라인 항목 작성
- Leaflet 장소 지도

### 4.3 버킷리스트

역할:

- 가고 싶은 여행지를 관리한다.
- 버킷리스트 항목을 예정 여행으로 전환한다.

진입 화면:

- 버킷리스트 목록
- 버킷리스트 등록/수정
- 예정 여행 전환 화면

### 4.4 통계

역할:

- 여행 이력을 숫자와 차트로 회고한다.
- 연도별, 국가별, 국내 지역별, 월별 여행 패턴을 보여준다.

진입 화면:

- 통계 요약
- 연도별 여행 횟수/일수 차트
- 국가별/국내 지역별 방문 횟수
- 월별 여행 빈도

### 4.5 마이

역할:

- 계정 정보, 앱 설정, 데이터 관리, 로그아웃 진입점이다.
- MVP에서는 단순 계정/설정 화면으로 유지한다.

진입 화면:

- 내 프로필
- 계정 설정
- 데이터/샘플 데이터 안내
- 로그아웃

## 5. 핵심 화면 목록

### 5.1 홈 대시보드

화면 목적:

- 사용자의 전체 여행 이력을 지도와 핵심 숫자로 한눈에 보여준다.

핵심 정보:

- 세계지도/국내지도 토글
- react-simple-maps 지도
- 방문 국가 수
- 방문 국내 지역 수
- 총 여행 횟수
- 총 여행 일수
- 예정 여행
- 다가오는 체크리스트
- 최근 여행 기록

주요 사용자 액션:

- 세계지도/국내지도 전환
- 국가 또는 지역 선택
- 예정 여행 상세 진입
- 체크리스트 진입
- 최근 여행 상세 진입

모바일 화면에서 강조해야 할 요소:

- 지도는 첫 화면에서 가장 큰 시각 요소여야 한다.
- 요약 지표는 2열 작은 카드로 빠르게 스캔 가능해야 한다.
- 예정 여행과 체크리스트는 하단으로 내려가며 자연스럽게 다음 행동을 유도한다.

필요한 컴포넌트:

- `AppHeader`
- `MapModeToggle`
- `DashboardMap`
- `StatCard`
- `UpcomingTripCard`
- `ChecklistProgressCard`
- `RecentTripCard`
- `BottomSheet`

### 5.2 여행 목록

화면 목적:

- 여행을 상태별로 탐색하고 새 여행을 등록한다.

핵심 정보:

- 예정 여행
- 다녀온 여행
- 취소된 여행
- 대표 이미지
- 여행명
- 여행 기간
- 지역
- 상태
- 체크리스트 진행률

주요 사용자 액션:

- 여행 생성
- 상태별 필터 변경
- 여행 상세 진입
- 여행 수정/삭제

모바일 화면에서 강조해야 할 요소:

## 6. 홈 대시보드 상세 구조

홈 대시보드는 서비스의 핵심 화면이다. 디자인 시안에서는 이 화면을 가장 구체적으로 보여줘야 한다.

### 6.1 권장 화면 구조

```txt
상단 앱 헤더
-> 인사말 또는 서비스명
-> 세계지도/국내지도 토글
-> react-simple-maps 지도 영역
-> 지도 선택 결과 바텀시트 또는 접힌 요약 패널
-> 핵심 지표 2열 카드
-> 예정 여행 카드
-> 다가오는 체크리스트
-> 최근 여행 기록
-> 하단 탭 네비게이션
```

### 6.2 상단 영역

구성:

- 앱 이름 또는 짧은 인사말
- 오늘 기준 예정 여행 알림
- 프로필 또는 설정 진입 아이콘

디자인 방향:

- 헤더는 과하게 크지 않게 유지한다.
- 지도 영역이 첫 화면의 중심이 되도록 상단 텍스트는 짧게 둔다.

### 6.3 세계지도/국내지도 토글

요구사항:

- 지도 상단에 세그먼트 컨트롤 형태로 배치한다.
- 옵션은 `세계지도`, `국내지도` 두 가지다.
- 선택된 모드는 명확한 배경색과 텍스트 대비로 구분한다.

상태:

- 세계지도 선택: 국가 단위 색칠 지도 표시
- 국내지도 선택: 국내 시/도 단위 색칠 지도 표시

### 6.4 react-simple-maps 지도 영역

요구사항:

- 모바일 화면에서 가로폭을 충분히 사용한다.
- 지도 영역은 카드처럼 보일 수 있으나 지나치게 장식적이지 않아야 한다.
- 색상 의미는 완료, 예정, 버킷리스트를 구분한다.

지도 상태 색상:

- 완료: 가장 강한 강조색
- 예정: 중간 강조색
- 버킷리스트: 보조 강조색
- 데이터 없음: 낮은 대비의 중립색

인터랙션:

- 국가 또는 지역 터치 시 바텀시트가 열린다.
- 바텀시트에는 해당 국가/지역의 완료 여행, 예정 여행, 버킷리스트 항목을 모두 보여준다.

바텀시트 구체 구조:

```txt
선택한 국가 또는 지역명
-> 상태 요약: 완료 N건 / 예정 N건 / 버킷리스트 N건
-> 완료 여행 목록
-> 예정 여행 목록
-> 버킷리스트 목록
-> 관련 전체 보기 또는 상세 이동 버튼
```

바텀시트 표시 규칙:

- 기본 상태는 화면 하단 35-45% 높이로 연다.
- 위로 끌어올리면 80-90% 높이까지 확장할 수 있다.
- 닫기 버튼과 아래로 스와이프 닫기를 모두 지원한다.
- 지도 자체를 가리지 않도록 반투명 오버레이 사용은 최소화한다.

### 6.5 핵심 지표 카드

필수 지표:

- 방문 국가 수
- 방문 국내 지역 수
- 총 여행 횟수
- 총 여행 일수

디자인 방향:

- 2열 그리드로 배치한다.
- 숫자는 크고, 라벨은 작고 명확하게 표현한다.
- 지도와 같은 색상 체계를 사용하되 과도한 색상 사용은 피한다.

### 6.6 예정 여행 카드

표시 정보:

- 여행명
- 여행 기간
- 국가 또는 지역
- D-day 또는 남은 기간
- 체크리스트 진행률

주요 액션:

- 여행 상세로 이동
- 체크리스트 바로가기

디자인 방향:

- 예정 여행이 있으면 홈에서 가장 강한 다음 행동 카드로 보여준다.
- 예정 여행이 없으면 버킷리스트 등록 또는 여행 생성으로 유도하는 빈 상태를 보여준다.

### 6.7 다가오는 체크리스트

표시 정보:

- 여행명
- 체크리스트 진행률
- 미완료 항목 수
- 가까운 마감 항목

주요 액션:

- 체크리스트 화면으로 이동
- 빠른 완료 체크는 홈에서는 제공하지 않아도 된다.

### 6.8 최근 여행 기록

표시 정보:

- 대표 이미지
- 여행명
- 여행 기간
- 지역
- 최근 기록된 타임라인 또는 사진 수

주요 액션:

- 여행 상세로 이동
- 타임라인 이어쓰기

## 7. 여행 상세 화면 구조

여행 상세는 하나의 여행을 준비하고 기록하는 중심 화면이다.

### 7.1 상단 대표 이미지와 기본 정보

구성:

- 대표 이미지
- 여행명
- 여행 기간
- 국가 또는 국내 지역
- 도시
- 상태 배지
- 여행 유형 또는 동행자

디자인 방향:

- 대표 이미지는 상단 히어로로 배치한다.
- 이미지 위 텍스트는 대비가 충분할 때만 사용하고, 아니면 이미지 아래 정보 영역으로 분리한다.
- 상태 배지는 `PLANNED`, `COMPLETED`, `CANCELLED`를 명확히 구분한다.

### 7.2 내부 탭 또는 섹션 구조

권장 탭:

- 개요
- 타임라인
- 체크리스트
- 지도
- 사진

탭 설계:

- 모바일에서는 상단 sticky 탭 또는 가로 스크롤 탭을 사용한다.
- 예정 여행은 체크리스트 탭을 더 강조한다.
- 완료 여행은 타임라인, 지도, 사진 탭을 더 강조한다.

### 7.3 개요 탭

표시 정보:

- 여행 기본 정보
- 체크리스트 진행률 요약
- 타임라인 작성 현황
- 대표 사진
- 메모

주요 액션:

- 여행 정보 수정
- 상태 변경
- 체크리스트 또는 타임라인으로 이동

### 7.4 타임라인 탭

구성:

- 날짜 선택 칩: Day 1, Day 2, 날짜
- 타임라인 리스트
- 항목 추가 버튼

타임라인 항목 표시:

- 시간
- 제목
- 장소명
- 메모 일부
- 사진 썸네일
- 비용 또는 카테고리

### 7.5 체크리스트 탭

구성:

- 진행률 카드
- 카테고리별 체크리스트
- 항목 추가 버튼

디자인 방향:

- 체크 완료 액션을 가장 쉽게 만든다.
- 완료된 항목은 흐리게 표시하고 체크 아이콘을 명확히 보여준다.

### 7.6 지도 탭

구성:

- Leaflet 장소 지도
- 장소 핀
- 핀 선택 바텀시트
- 연결된 타임라인 항목 리스트

원칙:

- 상세지도는 장소 핀 표시만 한다.
- 지역 색칠은 하지 않는다.
- 지도에서 직접 장소 추가, 동선 라인 표시는 MVP에서 제외한다.

### 7.7 사진 탭

구성:

- 사진 그리드
- 타임라인 항목 연결 정보
- 사진 추가 버튼

디자인 방향:

- MVP에서는 복잡한 앨범 기능보다 사진 목록과 연결된 기록 확인에 집중한다.
- 사진을 누르면 간단한 확대 보기 또는 상세 바텀시트를 제공할 수 있다.

## 8. 지도 UI 설계 방향

### 8.1 세계지도

- 해외여행 국가 단위 색칠 지도다.
- 국가별로 완료, 예정, 버킷리스트 상태를 표시한다.
- 같은 국가에 여러 상태가 있으면 `COMPLETED > PLANNED > BUCKET` 우선순위를 따른다.
- 도시 단위 색칠은 하지 않는다.

### 8.2 국내지도

- MVP에서는 시/도 단위 색칠 지도다.
- 시/군/구 단위 색칠은 후순위 확장이다.
- 국내 지역별 완료, 예정, 버킷리스트 상태를 표시한다.
- 광안리처럼 세부 장소를 다녀온 경우 MVP 지도에서는 부산광역시 단위로 표시한다.

### 8.3 상세지도

- 여행 상세에서만 사용한다.
- Leaflet 기반 장소 핀 지도다.
- 타임라인 항목의 위도/경도를 마커로 표시한다.
- 색칠 지도, 지역 집계, 동선 라인은 MVP에 포함하지 않는다.

### 8.4 세계/국내 지도 전환 UI

권장 방식:

- 지도 상단 세그먼트 컨트롤
- 라벨: `세계지도`, `국내지도`
- 토글 주변에는 연도 필터 같은 추가 컨트롤을 MVP에서 넣지 않는다.

이유:

- 홈 대시보드의 핵심은 전체 현황을 빠르게 보는 것이다.
- MVP에서 지도 필터가 많아지면 모바일 화면이 복잡해진다.

### 8.5 지도 위 요약 카드와 바텀시트

권장 방식:

- 지도 위에는 작은 범례 또는 선택 상태만 올린다.
- 상세 목록은 바텀시트로 보여준다.

바텀시트 내용:

- 선택한 국가 또는 지역명
- 완료 여행 목록
- 예정 여행 목록
- 버킷리스트 항목
- 관련 상세 화면으로 이동하는 버튼

이 방식의 장점:

- 모바일 지도 영역을 가리지 않는다.
- 사용자가 선택한 지역의 정보를 앱처럼 자연스럽게 확인할 수 있다.
- 이후 시/군/구 확장이나 필터 확장에도 구조가 유지된다.

## 9. 디자인 시안 3개 생성을 위한 컨셉 제안

`docs/design/concept_mobile.png`와 `docs/design/concept_web.png`는 아래 컨셉 중 **컨셉 A: 감성적인 여행 기록장 스타일**의 초기 기준안으로 본다. `concept_*` 파일을 제외한 나머지 화면별 시안은 최종 디자인 시스템 확정 기준으로 사용한다.

### 9.1 컨셉 A: 감성적인 여행 기록장 스타일

분위기:

- 개인 여행 일기, 사진첩, 기록장의 느낌
- 따뜻하지만 과하게 꾸미지 않은 감성

컬러 방향:

- 따뜻한 오프화이트 배경
- 차분한 그린 또는 코랄 계열 포인트
- 지도 색상은 부드러운 채도 사용

레이아웃 특징:

- 대표 이미지와 최근 여행 기록이 돋보인다.
- 카드 간 여백이 넉넉하다.
- 타임라인은 일기장처럼 읽히는 세로 구조를 사용한다.

강조 화면:

- 여행 상세
- 최근 여행 기록
- 타임라인
- 사진 그리드

장점:

- 개인 아카이브 서비스의 정서가 잘 전달된다.
- 여행 후 기록과 회고에 강하다.

단점:

- 지도 대시보드와 통계의 데이터 서비스 느낌은 약해질 수 있다.
- 포트폴리오에서 기술적 밀도가 덜 드러날 수 있다.

### 9.2 컨셉 B: 지도 대시보드 중심 스타일

분위기:

- 지도, 지표, 상태가 중심인 여행 데이터 대시보드
- 깔끔하고 시각적으로 명확한 앱 느낌

컬러 방향:

- 밝은 중립 배경
- 완료/예정/버킷리스트 상태를 구분하는 선명한 포인트 컬러
- 지도와 통계 차트의 색상 체계를 일관되게 사용

레이아웃 특징:

- 홈 첫 화면에서 지도 비중이 가장 크다.
- 요약 지표 카드와 예정 여행 카드가 지도 아래에 밀도 있게 배치된다.
- 바텀시트와 상태 배지 사용이 두드러진다.

강조 화면:

- 홈 대시보드
- 세계지도/국내지도 토글
- 지도 선택 바텀시트
- 통계

장점:

- PRD의 핵심인 지도 전략이 가장 잘 드러난다.
- 포트폴리오 시연에서 기능 구조를 설명하기 쉽다.

단점:

- 감성적인 여행 기록 앱 느낌은 상대적으로 줄어들 수 있다.
- 지도 영역이 커서 사진과 메모의 정서적 요소가 덜 부각될 수 있다.

### 9.3 컨셉 C: 미니멀 모바일 생산성 앱 스타일

분위기:

- 할 일 관리 앱과 여행 기록 앱을 결합한 실용적 분위기
- 반복 사용에 적합한 조용하고 정돈된 모바일 앱

컬러 방향:

- 화이트 또는 밝은 그레이 배경
- 블루그린, 인디고, 민트 중 하나를 제한적으로 사용
- 상태 배지는 채도 낮은 색상으로 구분

레이아웃 특징:

- 하단 탭, 리스트, 진행률, 체크리스트가 중심이다.
- 카드 디자인은 얇은 테두리와 작은 그림자 정도로 절제한다.
- 정보 밀도는 높지만 터치 영역은 충분히 확보한다.

강조 화면:

- 여행 목록
- 준비 체크리스트
- 버킷리스트
- 여행 상세 개요

장점:

- 실제 PWA로 구현하기 가장 안정적인 방향이다.
- 체크리스트와 여행 관리 흐름이 명확하다.

단점:

- 여행 서비스만의 개성이 약해질 수 있다.
- 디자인 시안에서 눈에 띄는 시각적 인상이 부족할 수 있다.

---

### 9.4 추가 생성이 필요한 보완 시안

현재 기준 시안에서 부족한 화면은 별도 시안으로 보완한다.

- 통계 탭 전용 화면: 요약 지표, 연도별 여행 횟수/일수, 월별 빈도, 국가/지역별 방문 순위를 독립 화면으로 보여준다.
- 마이페이지: 계정 정보, PWA 설치 안내, 데이터 관리, 로그아웃을 단순한 설정 리스트로 보여준다.
- 국내지도 모바일 화면: 세계지도와 동일한 구조로 국내 시/도 단위 색칠 지도를 보여준다.
- 지도 선택 바텀시트: 국가/지역 선택 후 완료 여행, 예정 여행, 버킷리스트 목록이 어떻게 표시되는지 보여준다.
- 버킷리스트 전환 화면: 버킷리스트 카드에서 예정 여행 전환 폼으로 이어지는 흐름을 보여준다.

## 10. 공통 컴포넌트 후보

- `BottomTabNavigation`: 홈, 여행, 버킷리스트, 통계, 마이 탭을 제공하는 모바일 하단 네비게이션.

- `StatusBadge`: 여행과 버킷리스트 상태를 색상과 라벨로 표시하는 배지.
- `PriorityBadge`: 버킷리스트 우선순위를 표시하는 배지.
- `StatCard`: 방문 국가 수, 여행 횟수 같은 핵심 숫자를 표시하는 카드.
- `ChartCard`: Recharts 차트를 감싸는 통계 카드.
- `SectionHeader`: 섹션 제목과 더보기/추가 액션을 담는 헤더.
- `EmptyState`: 데이터가 없을 때 다음 행동을 유도하는 빈 상태 컴포넌트.
- `FloatingActionButton`: 현재 화면의 주요 추가 액션을 제공하는 버튼.
- `BottomSheet`: 지도 선택 결과, 필터, 확인 액션, 마커 상세를 보여주는 하단 패널.
- `FilterChips`: 상태, 국내/해외, 우선순위, 연도 같은 필터를 칩으로 표시.
- `InternalTabBar`: 여행 상세 내부의 개요, 타임라인, 체크리스트, 지도, 사진 탭.
- `PhotoGrid`: 여행 사진을 모바일 그리드로 보여주는 컴포넌트.
- `ConfirmActionSheet`: 완료 처리, 삭제, 로그아웃 같은 확인이 필요한 액션을 처리하는 바텀시트.

## 11. 디자인 시스템 초안

### 11.1 컬러 방향

권장 기본 방향:

- 배경: 밝은 중립색
- 본문 텍스트: 높은 대비의 다크 그레이
- 보조 텍스트: 중간 대비 그레이
- 주요 액션: 여행과 지도에 어울리는 블루그린 또는 딥 틸
- 완료 상태: 안정적인 그린 계열
- 예정 상태: 블루 또는 인디고 계열
- 버킷리스트 상태: 코랄 또는 앰버 계열
- 위험 액션: 레드 계열

주의:

- 전체 앱이 한 가지 색상 계열로만 보이지 않게 한다.
- 지도, 배지, 차트 색상은 의미가 일관되어야 한다.

### 11.2 폰트 크기 체계

모바일 기준:

- 화면 제목: 22-24px
- 섹션 제목: 17-19px
- 카드 제목: 16-18px
- 본문: 14-16px
- 보조 텍스트: 12-13px
- 지표 숫자: 24-32px
- 배지/칩: 11-13px

원칙:

- 뷰포트 폭에 따라 폰트 크기를 자동 확대하지 않는다.
- 긴 여행명과 지역명은 줄바꿈 또는 말줄임 처리 기준을 둔다.

### 11.3 카드 스타일

- 카드 radius는 8px 이하를 기본으로 한다.
- 홈의 지표 카드와 여행 카드는 얇은 테두리 또는 약한 그림자로 구분한다.
- 카드 내부에 또 다른 카드를 중첩하지 않는다.
- 지도, 차트, 리스트는 같은 표면 규칙을 공유하되, 지도는 충분한 높이를 확보한다.

### 11.4 버튼 스타일

- 주요 버튼은 화면당 1개를 명확히 둔다.
- 아이콘이 있는 액션은 가능한 아이콘+짧은 텍스트를 사용한다.
- 체크, 추가, 편집, 삭제, 지도 전환 등 반복 액션은 익숙한 아이콘을 사용한다.
- 파괴적 액션은 색상과 확인 절차로 구분한다.

### 11.5 배지 스타일

여행 상태:

- `PLANNED`: 예정
- `COMPLETED`: 완료
- `CANCELLED`: 취소

버킷리스트 상태:

- `WANT_TO_GO`: 가고 싶음
- `PLANNING`: 계획 중
- `BOOKED`: 예약 완료
- `VISITED`: 다녀옴
- `ON_HOLD`: 보류

원칙:

- 배지는 작은 면적에서도 상태가 명확해야 한다.
- 색상만으로 의미를 전달하지 않고 텍스트 라벨을 함께 사용한다.

### 11.6 지도 오버레이 스타일

- 지도 위 오버레이는 최소화한다.
- 범례는 작은 칩 또는 접이식 정보로 제공한다.
- 국가/지역 선택 상세는 바텀시트로 보여준다.
- 바텀시트는 지도 하단 일부만 덮는 기본 상태와 더 크게 펼친 상태를 지원할 수 있다.

### 11.7 간격/여백 규칙

- 화면 좌우 기본 여백: 16px
- 카드 간 간격: 12-16px
- 섹션 간 간격: 24-32px
- 리스트 아이템 높이: 최소 56px 권장
- 하단 탭 위 마지막 콘텐츠 여백: 80px 이상

### 11.8 모바일 터치 영역 기준

- 주요 터치 타깃은 최소 44px 이상으로 설계한다.
- 체크박스와 아이콘 버튼은 시각 크기가 작아도 터치 영역을 넓게 잡는다.
- 지도 마커는 모바일에서 누르기 쉬운 크기와 충분한 간격을 가진다.
- 스와이프 액션은 보조 액션으로만 사용하고 필수 액션은 명시 버튼으로 제공한다.

### 11.9 PWA safe-area 고려사항

- 하단 탭은 iOS safe-area inset을 고려해 하단 여백을 확보한다.
- 플로팅 액션 버튼은 하단 탭과 겹치지 않아야 한다.
- 상단 헤더는 모바일 브라우저 주소창 변화와 PWA standalone 모드를 모두 고려한다.
- 바텀시트의 하단 액션 버튼은 홈 인디케이터 영역과 겹치지 않아야 한다.

## 12. 이미지 생성 AI 요청용 최종 프롬프트 초안

아래 프롬프트는 ChatGPT-image2.0 같은 이미지 생성 모델에게 모바일 PWA 화면 디자인 시안 3개를 요청하기 위한 초안이다.

```txt
모바일 PWA 기반의 개인 여행 아카이브 서비스 화면 디자인 시안 3가지를 생성해줘.

서비스 개요:
가고 싶은 곳, 준비 중인 여행, 다녀온 여행을 하나의 지도와 타임라인으로 관리하는 개인 여행 아카이브 앱이다. 사용자는 버킷리스트를 만들고, 예정 여행으로 전환하고, 체크리스트로 준비하고, 여행 후 날짜별 타임라인/사진/메모/장소 핀을 기록하고, 세계지도/국내지도/통계로 여행 이력을 회고한다.

전제:
- 이 서비스는 웹 기반 Next.js PWA이지만, 모바일 사용성을 1차 기준으로 한다.
- 모바일 사용성을 우선하는 PWA 앱이다.
- 데스크탑 웹 화면은 같은 디자인 시스템을 확장한 포트폴리오 시연용 반응형 대시보드로 제안한다.
- 하단 탭 네비게이션을 사용한다.
- 탭은 홈, 여행, 버킷리스트, 통계, 마이다.
- 프론트엔드는 Next.js App Router로 개발될 예정이다.
- 홈 대시보드가 가장 중요한 화면이다.
- 지도 역할은 분리된다.
  - 세계/국내 대시보드 지도: react-simple-maps 기반 색칠 지도
  - 여행 상세 장소 지도: Leaflet 기반 장소 핀 지도
- MVP 기준이며 과도한 기능은 추가하지 않는다.

반드시 포함할 화면 요소:
1. 홈 대시보드 중심 화면
   - 세계지도/국내지도 토글
   - react-simple-maps 스타일 지도 영역
   - 방문 국가 수
   - 방문 국내 지역 수
   - 총 여행 횟수
   - 총 여행 일수
   - 예정 여행 카드
   - 다가오는 체크리스트
   - 최근 여행 기록
2. 여행 상세 화면 일부
   - 대표 이미지
   - 여행명, 기간, 지역
   - 상태 배지
   - 내부 탭: 개요, 타임라인, 체크리스트, 지도, 사진
   - Leaflet 스타일 장소 지도와 장소 핀
   - 날짜별 타임라인 일부
3. 버킷리스트 요소
   - 가고 싶은 여행지 카드
   - 우선순위, 상태, 희망 시기
   - 예정 여행으로 전환 버튼
4. 체크리스트 요소
   - 진행률 카드
   - 카테고리별 체크 항목
5. 통계 요소
   - 연도별 여행 횟수/일수
   - 방문 국가/국내 지역 요약
   - 간단한 차트 카드
6. 마이페이지 요소
   - 사용자 이메일
   - PWA 설치 안내
   - 데이터 관리 메뉴
   - 로그아웃 버튼

3가지 서로 다른 디자인 컨셉:

컨셉 A: 감성적인 여행 기록장 스타일
- 분위기: 개인 여행 일기, 사진첩, 기록장 느낌
- 컬러: 따뜻한 오프화이트 배경, 차분한 그린 또는 코랄 포인트
- 특징: 대표 이미지, 최근 여행 기록, 타임라인, 사진 그리드를 강조

컨셉 B: 지도 대시보드 중심 스타일
- 분위기: 지도, 지표, 상태가 중심인 여행 데이터 대시보드
- 컬러: 밝은 중립 배경, 완료/예정/버킷리스트 상태가 명확히 구분되는 포인트 컬러
- 특징: 홈 지도 영역이 가장 크고, 요약 지표와 지도 선택 바텀시트를 강조

컨셉 C: 미니멀 모바일 생산성 앱 스타일
- 분위기: 할 일 관리 앱과 여행 기록 앱을 결합한 실용적이고 정돈된 느낌
- 컬러: 화이트/라이트 그레이 기반, 블루그린 또는 인디고 포인트
- 특징: 여행 목록, 체크리스트, 버킷리스트, 상태 배지, 진행률을 강조

디자인 기준:
- 실서비스처럼 정돈된 UI여야 한다.
- 모바일 PWA 화면 비율로 보여줘.
- 하단 탭 네비게이션과 safe-area를 고려해줘.
- 지도, 카드, 바텀시트, 배지, 체크리스트, 차트가 실제 앱처럼 자연스럽게 보여야 한다.
- 텍스트가 UI 요소 안에서 겹치거나 잘리지 않게 해줘.
- 과도한 마케팅 랜딩 페이지처럼 만들지 말고, 사용자가 바로 조작하는 앱 화면으로 보여줘.
- 각 컨셉은 최소 홈 대시보드 1장과 여행 상세 일부가 함께 보이도록 구성해줘.
- 추가 보완 시안으로 통계 탭 전용 화면과 마이페이지 화면도 별도로 보여줘.
- 모바일 시안은 실제 PWA 구현 기준으로, 웹 시안은 포트폴리오 시연용 보조 대시보드 기준으로 구분해줘.
- 모바일과 웹이 서로 다른 제품처럼 보이지 않게, 색상/카드/배지/지도/탭/차트 스타일은 일관되게 유지해줘.
```

## 부록: MVP와 후순위 구분

MVP 디자인에 반드시 보여줄 것:

- 하단 탭 네비게이션
- 홈 대시보드
- 세계지도/국내지도 토글
- 세계지도 국가 단위 색칠
- 국내지도 시/도 단위 색칠
- 여행 목록과 여행 상세
- 체크리스트
- 날짜별 타임라인
- Leaflet 장소 핀 지도
- 버킷리스트와 예정 여행 전환 CTA
- 기본 통계

후순위로만 암시할 수 있는 것:

- 시/군/구 단위 국내지도
- 동선 라인
- 외부 장소 검색
- AI 여행 추천
- 공유 페이지
- PWA 오프라인 보기
- 푸시 알림
- 여행 가계부
- 이미지 썸네일 자동 생성
