# 개인 여행 아카이브 서비스 PRD

작성일: 2026-05-08  
기준 문서: `travel_archive_prd_reference.md`  
서비스명: 미정. 본 문서에서는 임시로 "개인 여행 아카이브"라고 지칭한다.

---

## 1. 제품 개요

### 1.1 한 줄 정의

가고 싶은 곳, 준비 중인 여행, 다녀온 여행을 하나의 지도와 타임라인으로 관리하는 개인 여행 아카이브 서비스.

### 1.2 핵심 컨셉

이 서비스는 여행을 단순히 기록하는 앱이 아니라, 여행 전후의 흐름을 하나로 연결한다.

1. 가고 싶은 곳을 버킷리스트로 저장한다.
2. 실제로 갈 여행으로 전환한다.
3. 출발 전 준비 체크리스트를 관리한다.
4. 다녀온 뒤 사진, 메모, 타임라인, 장소 핀을 기록한다.
5. 세계지도, 국내지도, 통계로 여행 이력을 회고한다.

### 1.3 제품 목표

- 사용자가 가고 싶은 여행지, 예정 여행, 다녀온 여행을 한 곳에서 관리할 수 있게 한다.
- 버킷리스트에서 예정 여행, 완료 여행 기록까지 이어지는 자연스러운 흐름을 제공한다.
- 세계지도, 국내지도, 상세 장소 지도의 역할을 분리해 여행 이력을 시각적으로 보여준다.
- 모바일 우선 UI로 실제 개인 사용자가 반복적으로 기록하고 확인할 수 있는 경험을 제공한다.
- 포트폴리오 관점에서 Spring Boot REST API, JWT 인증, PostgreSQL, Next.js App Router, 이미지 업로드, 지도 시각화, 통계 집계, 배포 역량을 보여준다.

## 2. 사용자와 문제 정의

### 2.1 대상 사용자

주 대상 사용자는 개인 여행자다.

- 가고 싶은 여행지를 자주 저장하지만 실제 계획과 기록이 흩어지는 사용자
- 여행 준비 체크리스트를 여행별로 관리하고 싶은 사용자
- 다녀온 여행을 사진, 장소, 날짜별 메모와 함께 정리하고 싶은 사용자
- 내가 다녀온 국가와 국내 지역을 지도와 통계로 보고 싶은 사용자

### 2.2 해결할 문제

- 버킷리스트, 여행 준비, 여행 기록, 여행 회고가 서로 다른 도구에 흩어진다.
- 지도 기반 회고와 날짜별 타임라인 기록이 자연스럽게 연결되지 않는다.
- 국내여행과 해외여행은 지도 표현 단위가 다른데, 많은 서비스가 이를 명확히 분리하지 않는다.
- 포트폴리오 프로젝트로 구현할 때 기능 범위가 쉽게 커져 MVP 완성도가 낮아질 수 있다.

## 4. 핵심 사용자 흐름

### 4.1 버킷리스트 등록 흐름

사용자는 언젠가 가고 싶은 여행지를 버킷리스트로 등록한다.

필수 입력값:

- 여행지명
- 여행 범위: 국내 / 해외
- 해외인 경우 국가
- 국내인 경우 시/도
- 도시명 또는 지역명

선택 입력값:

- 국내 세부 지역: 시/군/구
- 가고 싶은 이유
- 희망 시기
- 예상 예산
- 우선순위
- 태그
- 참고 링크
- 상태
- 메모

버킷리스트 상태:

- `WANT_TO_GO`: 가고 싶음
- `PLANNING`: 계획 중
- `BOOKED`: 예약 완료
- `VISITED`: 다녀옴
- `ON_HOLD`: 보류

### 4.2 버킷리스트를 예정 여행으로 전환

사용자는 버킷리스트 항목을 실제 예정 여행으로 전환할 수 있다.

전환 시 생성되는 정보:

- 여행명
- 여행 기간
- 여행 범위: 국내 / 해외
- 국가 또는 국내 지역
- 도시명
- 여행 상태: `PLANNED`
- 기본 준비 체크리스트

전환 규칙:

- 예정 여행 생성 필수값은 여행명, 국내/해외 구분, 국가 또는 국내 시/도, 도시명, 여행 시작일, 여행 종료일이다.
- 원본 버킷리스트 항목은 `PLANNING` 또는 `BOOKED` 상태로 변경할 수 있다.
- 전환 후에도 버킷리스트 항목은 삭제하지 않고 사용자의 여행 히스토리 후보로 유지한다.

### 4.3 여행 준비 체크리스트

예정 여행을 생성하면 기본 체크리스트를 제공한다.

공통 기본 항목:

- 숙소 예약 확인
- 이동 수단 확인
- 날씨 확인
- 보조배터리
- 충전기
- 상비약
- 세면도구

해외여행 추가 항목:

- 여권 확인
- 항공권 확인
- 여행자보험 확인
- 환전
- eSIM 또는 로밍 준비
- 여권 사본 준비
- 현지 교통패스 확인
- 콘센트 어댑터 확인

국내여행 추가 항목:

- 숙소 체크인 시간 확인
- 차량 이동 여부 확인
- 렌터카 또는 대중교통 확인
- 지역 날씨 확인

체크리스트 요구사항:

- 항목 추가, 수정, 삭제가 가능해야 한다.
- 항목 완료 체크가 가능해야 한다.
- 카테고리별로 항목을 구분할 수 있어야 한다.
- 진행률을 계산해 여행 목록과 체크리스트 화면에 표시해야 한다.

### 4.4 다녀온 여행 기록

사용자는 예정 여행을 완료 상태로 변경하고 여행 기록을 작성한다.

상태 전환:

```txt
PLANNED -> COMPLETED
PLANNED -> CANCELLED
```

완료 처리 조건:

- 여행 시작일과 종료일이 입력되어 있어야 한다.
- 최소 1개 이상의 `trip_day`가 생성되어 있어야 한다.
- MVP에서는 타임라인, 사진, 장소 핀은 완료 처리 후에도 추가 가능하다.

완료 후 수정 가능 범위:

- 날짜별 타임라인 추가, 수정, 삭제
- 사진 추가, 수정, 삭제
- 메모 수정
- 장소 핀 추가, 수정, 삭제
- 대표 이미지 변경

취소 상태 규칙:

- `CANCELLED` 여행은 완료 여행 통계와 지도 색칠 집계에서 제외한다.
- 목록과 필터에서는 조회 가능해야 한다.
- 취소 여행은 기본 정보와 메모 수정만 허용한다.

## 5. 지도 전략

### 5.1 지도 역할 분리 원칙

서비스는 지도 기능을 세 가지로 분리한다.

1. 해외여행용 세계지도
2. 국내여행용 한국지도
3. 여행 상세용 장소 지도

원칙:

- 색칠 지도는 지역 단위 상태 표현용이다.
- 상세 지도는 실제 방문 장소 핀 표시용이다.
- 세계지도와 국내지도는 대시보드 역할을 한다.
- 여행 상세 지도는 기록 탐색 역할을 한다.

### 5.2 해외여행 지도

목적:

- 해외여행은 세계지도에서 국가 단위로 표시한다.
- 도쿄, 오사카, 후쿠오카 같은 도시를 세계지도에서 색칠하지 않는다.
- 도시 정보는 여행 상세 또는 여행 목록에서 보여준다.

사용 라이브러리:

- `react-simple-maps`

MVP 요구사항:

- 방문 완료 국가 색칠
- 버킷리스트 국가 표시
- 예정 여행 국가 표시
- 국가 클릭 시 해당 국가와 관련된 완료 여행, 예정 여행, 버킷리스트 목록 표시

후순위:

- 국가별 방문 횟수 히트맵
- 연도별 필터
- 여행 유형별 필터
- 대륙별 통계

### 5.3 국내여행 지도

목적:

- 국내여행은 한국지도에서 지역 단위로 표시한다.
- MVP에서는 시/도 단위만 색칠한다.
- 시/군/구 단위 색칠은 후순위 확장으로 둔다.

사용 라이브러리:

- `react-simple-maps`

MVP 요구사항:

- 시/도 단위 한국지도
- 방문 지역 색칠
- 버킷리스트 지역 표시
- 예정 여행 지역 표시
- 지역 클릭 시 관련 여행과 버킷리스트 목록 표시

후순위:

- 시/군/구 단위 한국지도
- 지역별 방문 횟수 히트맵
- 연도별 국내여행 필터
- 국내 여행 유형별 필터

### 5.4 여행 상세 지도

목적:

- 실제 장소를 핀으로 표시한다.
- 타임라인 항목과 장소 핀을 연결한다.
- 상세지도에서는 지역 색칠을 하지 않는다.

사용 라이브러리:

- `Leaflet`

MVP 요구사항:

- 여행 상세 페이지에 Leaflet 지도 표시
- 타임라인 항목별 위도/경도 저장
- 저장된 장소를 마커로 표시
- 마커 클릭 시 시간, 제목, 장소명, 메모, 사진 요약 표시

후순위:

- 날짜별 동선 라인 표시
- 장소 카테고리별 마커 아이콘 분리
- 지도에서 장소 직접 추가
- 여행별 전체 경로 보기

### 5.5 지도 상태 우선순위

같은 국가 또는 국내 지역에 여러 상태가 함께 존재할 수 있다.

색상 우선순위:

```txt
COMPLETED > PLANNED > BUCKET
```

규칙:

- 완료 여행 이력이 있으면 완료 색상을 우선 표시한다.
- 예정 여행만 있으면 예정 색상을 표시한다.
- 버킷리스트만 있으면 버킷리스트 색상을 표시한다.
- `CANCELLED` 여행과 `ON_HOLD` 버킷리스트는 지도 색칠 대상에서 제외한다.
- 지도 클릭 패널에서는 우선 색상과 별개로 해당 국가/지역의 완료 여행, 예정 여행, 버킷리스트 항목을 모두 보여준다.

### 5.6 지도 표시와 반응형 UI 규칙

홈 대시보드의 지도는 화면 크기에 따라 다음 기준으로 표시한다.

- 모바일 MVP 기준: 세계지도와 국내지도를 동시에 보여주지 않고, `세계지도 / 국내지도` 토글로 하나의 지도만 표시한다.
- 태블릿/데스크탑 기준: 기본은 모바일과 동일한 단일 지도+토글 구조를 유지한다. 포트폴리오 시연 화면에서는 여백이 충분한 경우 세계지도와 국내지도를 2개 카드로 병렬 배치할 수 있다.
- 지도 영역은 고정된 최소 높이를 가져야 하며, 데이터 로딩 전후에 레이아웃이 크게 흔들리지 않아야 한다.

지도 범례와 상태 색상은 다음 의미를 유지한다.

- `COMPLETED`: 방문 완료. 가장 강한 강조색으로 표시한다.
- `PLANNED`: 예정 여행. 중간 강조색으로 표시한다.
- `BUCKET`: 버킷리스트. 보조 강조색으로 표시한다.
- 데이터 없음: 낮은 대비의 중립색으로 표시한다.

지도 인터랙션:

- 세계지도에서 국가를 클릭하면 해당 국가의 완료 여행, 예정 여행, 버킷리스트 항목을 바텀시트 또는 사이드 패널로 보여준다.
- 국내지도에서 시/도를 클릭하면 해당 지역의 완료 여행, 예정 여행, 버킷리스트 항목을 바텀시트 또는 사이드 패널로 보여준다.
- 모바일에서는 바텀시트를 기본으로 사용한다.
- 데스크탑에서는 사이드 패널 또는 바텀시트를 사용할 수 있으나, 동일한 정보 구조를 유지해야 한다.

## 6. 화면 요구사항

### 6.1 홈 대시보드

홈은 서비스의 첫 화면이며 기본 화면은 세계지도다.

**라우팅 분리:**
- `/` — 비로그인 접근 가능한 **공개 홈**. 샘플 데이터 기반 미리보기와 가입/로그인 유도 CTA를 제공합니다.
- `/dashboard` — 로그인 필요. 실제 사용자 데이터를 적용한 홈 대시보드입니다.

구성:

- 세계지도 / 국내지도 전환 토글
- 세계지도 또는 국내지도
- 총 방문 국가 수
- 총 방문 국내 지역 수
- 총 여행 횟수
- 총 여행 일수
- 예정된 여행
- 다가오는 준비 체크리스트
- 최근 기록한 여행
- 지도 범례
- 예정 여행 D-day 또는 남은 기간

필수 동작:

- 지도 토글로 세계지도와 국내지도를 전환할 수 있어야 한다.
- 국가 또는 국내 지역 클릭 시 관련 항목 목록을 표시해야 한다.
- 모바일 화면에서도 지도와 요약 지표가 겹치지 않아야 한다.
- 모바일에서는 하나의 지도만 표시하고, 세계지도/국내지도 토글로 전환한다.
- 데스크탑에서는 단일 지도+토글을 기본으로 하되, 포트폴리오 시연 목적의 넓은 화면에서는 세계지도와 국내지도를 병렬 배치할 수 있다.
- 예정 여행 카드에는 D-day 또는 남은 기간을 표시할 수 있다.
- 다가오는 체크리스트는 홈에서 리마인더 카드로 표시하되, MVP에서는 푸시 알림을 제공하지 않는다.

### 6.2 여행 목록

여행 목록은 상태별로 구분한다.

탭 또는 필터:

- 예정 여행
- 다녀온 여행
- 취소된 여행

여행 카드 표시 정보:

- 대표 이미지
- 여행명
- 국내/해외 구분
- 국가 또는 국내 지역
- 도시
- 여행 기간
- 상태
- 여행 일수
- 체크리스트 진행률

필수 동작:

- 여행 생성, 상세 진입, 수정, 삭제가 가능해야 한다.
- 상태별 필터링이 가능해야 한다.
- 예정 여행은 체크리스트 진행률을 표시해야 한다.

### 6.3 여행 상세

여행 상세는 기록의 핵심 화면이다.

구성:

- 대표 이미지
- 여행명
- 여행 기간
- 국내/해외 구분
- 국가 또는 국내 지역
- 도시
- 동행자
- 여행 유형
- 준비 체크리스트
- 날짜별 타임라인
- 장소 지도
- 사진
- 메모

필수 동작:

- 여행 상태를 변경할 수 있어야 한다.
- 날짜별 타임라인을 생성, 수정, 삭제할 수 있어야 한다.
- 타임라인 항목에 장소명, 주소, 위도, 경도, 비용, 카테고리를 입력할 수 있어야 한다.
- 위도/경도가 있는 타임라인 항목은 Leaflet 지도에 마커로 표시해야 한다.
- 대표 이미지와 타임라인 사진을 업로드할 수 있어야 한다.

### 6.4 버킷리스트

버킷리스트 화면은 가고 싶은 여행지를 관리한다.

구성:

- 카드형 목록
- 국내/해외 구분
- 국가 또는 국내 지역
- 도시
- 우선순위
- 희망 시기
- 예상 예산
- 상태
- 태그
- 예정 여행으로 전환 버튼

필터:

- 국내/해외
- 국가
- 국내 시/도
- 국내 시/군/구
- 우선순위
- 상태
- 태그

필수 동작:

- 버킷리스트 항목을 생성, 수정, 삭제할 수 있어야 한다.
- 버킷리스트 항목을 예정 여행으로 전환할 수 있어야 한다.
- 전환 시 기본 여행 정보와 체크리스트가 생성되어야 한다.

예정 여행 전환 화면 필드:

- 여행명
- 여행 시작일
- 여행 종료일
- 국내/해외 구분
- 국가 또는 국내 시/도
- 도시명
- 동행자
- 여행 유형
- 메모

전환 완료 후 이동 규칙:

- 전환이 완료되면 생성된 여행 상세 화면으로 이동한다.
- 기본 진입 섹션은 체크리스트 또는 개요로 한다.
- 사용자가 즉시 준비 항목을 확인할 수 있도록 체크리스트 진행률과 기본 생성 항목을 노출한다.

### 6.5 준비 체크리스트

구성:

- 체크리스트 진행률
- 카테고리별 체크리스트
- 완료 체크
- 항목 추가, 수정, 삭제

카테고리 예시:

- 서류
- 짐
- 전자기기
- 건강/상비약
- 현지 준비

필수 동작:

- 체크 여부 변경 시 진행률이 즉시 갱신되어야 한다.
- 여행 구분에 따라 기본 템플릿이 다르게 생성되어야 한다.

### 6.6 통계 페이지

통계 페이지는 여행 기록을 데이터로 회고하는 화면이다.

MVP 표시 정보:

- 연도별 여행 횟수
- 연도별 여행 일수
- 해외 방문 국가 수
- 국내 방문 지역 수
- 국가별 방문 횟수
- 국내 지역별 방문 횟수

후순위 표시 정보:

- 도시별 방문 횟수
- 여행 유형 비율
- 총 여행 비용
- 대륙별 통계

차트 라이브러리:

- `Recharts`

MVP 차트 우선순위:

1. 연도별 여행 횟수와 여행 일수
2. 월별 여행 빈도
3. 국가별 방문 횟수
4. 국내 지역별 방문 횟수

도시별 방문 횟수, 여행 유형 비율, 총 여행 비용, 대륙별 통계는 후순위 확장으로 둔다.

### 6.7 마이페이지

마이페이지는 계정 상태와 앱 설정을 관리하는 최소 화면이다.

MVP 표시 정보:

- 사용자 이메일
- 내 프로필 요약
- PWA 설치 또는 앱 사용 안내
- 데이터 관리 메뉴
- 로그아웃

MVP 제외 또는 후순위:

- 상세 프로필 편집
- 소셜 계정 연결
- 공개 프로필
- 공유 페이지 관리
- 푸시 알림 설정

필수 동작:

- 사용자는 자신의 로그인 계정을 확인할 수 있어야 한다.
- 사용자는 로그아웃할 수 있어야 한다.
- 로그아웃은 확인 절차를 거친다.
- 마이페이지는 여행 기록, 버킷리스트, 통계의 핵심 기능을 침범하지 않는 설정 진입점으로 유지한다.

## 7. 기능 요구사항

### 7.1 인증

- 사용자는 이메일과 비밀번호로 회원가입할 수 있어야 한다.
- 사용자는 이메일과 비밀번호로 로그인할 수 있어야 한다.
- 로그인 성공 시 JWT를 발급해야 한다.
- 인증이 필요한 API는 JWT를 검증해야 한다.
- 사용자는 자신의 데이터만 조회, 생성, 수정, 삭제할 수 있어야 한다.

### 7.2 여행 관리

- 사용자는 여행을 생성, 조회, 수정, 삭제할 수 있어야 한다.
- 여행은 국내/해외 구분을 가진다.
- 여행은 `PLANNED`, `COMPLETED`, `CANCELLED` 상태를 가진다.
- 여행 기간을 기반으로 여행 일수를 계산해야 한다.
- 여행 상태별 목록 조회가 가능해야 한다.

### 7.3 버킷리스트 관리

- 사용자는 버킷리스트 항목을 생성, 조회, 수정, 삭제할 수 있어야 한다.
- 버킷리스트 항목은 국내/해외 구분을 가진다.
- 버킷리스트 항목은 상태, 우선순위, 희망 시기, 예상 예산, 태그, 참고 링크, 메모를 가질 수 있다.
- 사용자는 버킷리스트 항목을 예정 여행으로 전환할 수 있어야 한다.

### 7.4 체크리스트 관리

- 예정 여행 생성 시 기본 체크리스트를 자동 생성해야 한다.
- 사용자는 체크리스트 항목을 추가, 수정, 삭제할 수 있어야 한다.
- 사용자는 체크리스트 항목을 완료 처리할 수 있어야 한다.
- 체크리스트 진행률을 계산해 표시해야 한다.

### 7.5 타임라인 관리

- 여행은 여러 날짜(`trip_days`)를 가진다.
- 각 날짜는 여러 타임라인 항목을 가진다.
- 타임라인 항목은 시간, 제목, 메모, 장소, 주소, 위도, 경도, 비용, 카테고리, 정렬 순서를 가진다.
- 사용자는 타임라인 항목을 생성, 수정, 삭제할 수 있어야 한다.
- 타임라인 항목은 정렬 순서와 시간 기준으로 표시해야 한다.

### 7.6 사진 관리

- 사용자는 여행 대표 이미지를 업로드할 수 있어야 한다.
- 사용자는 타임라인 항목에 사진을 업로드할 수 있어야 한다.
- MVP에서는 로컬 파일 저장을 사용한다.
- 파일 저장 로직은 S3 호환 스토리지로 교체 가능하도록 인터페이스를 분리한다.
- MVP에서는 이미지 리사이징과 썸네일 자동 생성은 제외한다.

### 7.7 지도 집계

- 완료 여행은 지도와 통계의 완료 집계에 포함한다.
- 예정 여행은 지도에서 예정 상태로 표시한다.
- 버킷리스트는 지도에서 버킷 상태로 표시한다.
- 취소 여행과 보류 버킷리스트는 지도 색칠 대상에서 제외한다.
- 해외 지도 집계는 국가 코드 기준으로 처리한다.
- 국내 지도 집계는 MVP에서 시/도 코드 기준으로 처리한다.

### 7.8 통계 집계

- 연도별 여행 횟수를 집계해야 한다.
- 연도별 여행 일수를 집계해야 한다.
- 해외 방문 국가 수를 집계해야 한다.
- 국내 방문 시/도 수를 집계해야 한다.
- 국가별 방문 횟수를 집계해야 한다.
- 국내 지역별 방문 횟수를 집계해야 한다.
- 월별 여행 빈도를 집계해야 한다.

## 10. 기술 요구사항

### 10.1 Frontend

- Next.js App Router
- TypeScript
- Tailwind CSS
- `react-simple-maps`
- `Leaflet`
- `Recharts`

프론트엔드 요구사항:

- 모바일 우선 UI로 구현한다.
- 주요 화면은 모바일과 데스크톱에서 레이아웃 깨짐과 텍스트 겹침이 없어야 한다.
- 지도, 목록, 상세 화면 간 이동이 자연스러워야 한다.
- 생성/수정/삭제/상태 변경 후 화면 데이터가 갱신되어야 한다.

### 10.2 Backend

- Spring Boot 3.x
- Spring Security
- JWT
- JPA
- PostgreSQL

백엔드 요구사항:

- 사용자별 데이터 접근 제어를 보장한다.
- 상태 전환 규칙을 서버에서 검증한다.
- 지도와 통계 집계 API는 DB 기준으로 일관된 결과를 반환해야 한다.
- 이미지 업로드 저장소 로직은 인터페이스로 분리한다.

### 10.3 Storage

MVP에서는 로컬 파일 저장을 우선 사용한다.

요구사항:

- 업로드 파일은 사용자와 여행 기준으로 구분 가능한 경로에 저장한다.
- DB에는 접근 가능한 파일 URL 또는 경로를 저장한다.
- 저장소 구현은 추후 S3 호환 스토리지로 교체 가능해야 한다.

## 11. 완료 판정 기준

MVP는 다음 조건을 만족할 때 완료로 본다.

1. 로그인부터 통계 확인까지 필수 시연 흐름이 끊기지 않고 동작한다.
2. 해외 완료 여행 2건 이상, 국내 완료 여행 2건 이상, 예정 여행 1건 이상, 버킷리스트 3건 이상, 타임라인 장소 핀 5개 이상, 체크리스트 항목 10개 이상을 샘플 데이터로 제공한다.
3. 인증, 여행 CRUD, 버킷리스트 CRUD, 체크리스트 CRUD, 타임라인 CRUD, 이미지 업로드, 지도 집계, 통계 집계 API가 정상 동작한다.
4. 홈 대시보드, 여행 목록, 여행 상세, 버킷리스트, 준비 체크리스트, 통계 페이지가 MVP 화면으로 제공된다.
5. 주요 화면에서 생성, 조회, 수정, 삭제 또는 상태 변경이 가능하다.
6. 백엔드 핵심 서비스/API 테스트가 통과한다.
7. 프론트엔드 빌드와 백엔드 빌드가 성공한다.
8. PostgreSQL 연동이 확인된다.
9. 로컬 또는 홈서버/클라우드 배포 환경에서 전체 시연 흐름이 검증된다.
10. 모바일과 데스크톱에서 주요 화면의 텍스트와 UI 요소가 겹치지 않는다.

필수 시연 흐름:

```txt
로그인
-> 버킷리스트에 가고 싶은 여행지 등록
-> 버킷리스트를 예정 여행으로 전환
-> 여행 준비 체크리스트 확인 및 체크
-> 여행 완료 처리
-> 날짜별 타임라인과 사진 등록
-> Leaflet 지도에서 방문 장소 핀 확인
-> 홈 대시보드에서 세계지도 확인
-> 국내지도 토글로 국내 방문 지역 확인
-> 통계 페이지에서 여행 횟수와 여행 일수 확인
```

## 13. 리스크와 대응

### 13.1 지도 기능 범위 과다

리스크:

- 지도 기능은 확장성이 커서 MVP 범위를 초과하기 쉽다.

대응:

- 세계지도와 국내지도는 대시보드용 색칠 지도에 집중한다.
- 상세지도는 핀 표시에만 집중한다.
- 지도에서 장소 직접 추가, 동선 라인, 시/군/구 색칠은 후순위로 둔다.

### 13.2 지도 라이브러리 2개 사용

리스크:

- `react-simple-maps`와 `Leaflet`을 모두 사용해 개발 범위가 늘어난다.

대응:

- `react-simple-maps`는 대시보드 색칠 지도에서만 사용한다.
- `Leaflet`은 여행 상세 장소 지도에서만 사용한다.
- 각 라이브러리의 책임을 PRD와 코드 구조에서 명확히 분리한다.

### 13.3 국내 행정구역 데이터

리스크:

- 시/군/구 단위 지도는 GeoJSON 데이터와 코드 매핑이 복잡하다.

대응:

- MVP에서는 시/도 단위만 구현한다.
- 시/군/구 단위는 후순위 확장으로 분리한다.
- DB 구조는 시/군/구 확장이 가능하도록 `domestic_sub_region_code`와 `domestic_regions.parent_code`를 둔다.

### 13.4 이미지 업로드

리스크:

- 파일 저장, 용량 제한, 썸네일 처리, 접근 URL 관리가 추가 부담이 될 수 있다.

대응:

- MVP에서는 대표 이미지 1장과 타임라인 이미지 소수 업로드만 구현한다.
- 이미지 리사이징과 썸네일 자동 생성은 후순위로 둔다.
- 저장소 구현은 인터페이스로 분리해 S3 전환을 가능하게 한다.

### 13.5 기능 과다

리스크:

- 추천, 공유, AI, 외부 장소 검색 등 확장 아이디어가 많아 MVP 완성도가 낮아질 수 있다.

대응:

- MVP는 버킷리스트, 여행 기록, 체크리스트, 지도, 통계에 집중한다.
- 추천, 공유, AI, 외부 장소 검색은 제외한다.
- 한 달 안에 완성 가능한 화면 중심으로 개발한다.

## 15. PRD 요약

개인 여행 아카이브는 여행 전의 버킷리스트와 준비 체크리스트, 여행 후의 타임라인/사진/장소 핀 기록, 회고 단계의 세계지도/국내지도/통계를 하나로 연결하는 서비스다.

MVP는 이메일 인증, 여행 CRUD, 버킷리스트 전환, 체크리스트, 타임라인, 이미지 업로드, 지도 3종, 기본 통계에 집중한다. 지도는 역할을 명확히 나눈다. 세계지도는 국가 단위, 국내지도는 시/도 단위, 상세지도는 장소 핀 단위로 구현한다.

최종 완료 기준은 전체 시연 흐름이 실제 배포 환경에서 끊기지 않고 동작하며, 포트폴리오 평가자가 기술 스택, 데이터 모델, 지도 전략, 통계 집계, 모바일 UI, 배포 역량을 확인할 수 있는 상태다.
